# Source Policy — นโยบายการใช้แหล่งข้อมูล

**สถานะ:** ACTIVE  
**เวอร์ชัน:** v0.1  
**อ้างอิง:** `01 Constitution/EVIDENCE-POLICY.md`

---

## 1. Purpose

กำหนดหลักเกณฑ์ในการค้นหา คัดเลือก ประเมิน และใช้งาน Source ภายใน Research

---

## 2. Source Quality Dimensions

Source ต้องประเมินอย่างน้อยตาม:

- Authority — ผู้เผยแพร่มีความเชี่ยวชาญหรืออำนาจเกี่ยวข้องหรือไม่
- Relevance — ตรงกับคำถามหรือไม่
- Recency — ทันต่อช่วงเวลาที่ต้องการหรือไม่
- Provenance — ตรวจสอบที่มาได้หรือไม่
- Methodology — วิธีได้มาของข้อมูลน่าเชื่อถือหรือไม่
- Independence — มีความเป็นอิสระจากผลประโยชน์ที่อาจทำให้เกิด Bias หรือไม่
- Directness — Source รองรับ Claim โดยตรงหรือเป็นเพียงการกล่าวต่อ

ไม่มีเกณฑ์เดียวที่ใช้ตัดสิน Source ทุกประเภท

---

## 3. Source Hierarchy

โดยทั่วไปให้พิจารณา:

```text
Primary / First-party
        ↓
Official / Original Documents
        ↓
Original Research / Academic Sources
        ↓
High-quality Secondary Sources
        ↓
Expert Commentary
        ↓
Community / User-generated Sources
        ↓
Search snippets / Aggregators
```

ลำดับนี้เป็นแนวทาง ไม่ใช่กฎตายตัว เพราะ Source ที่เหมาะสมขึ้นอยู่กับคำถาม

---

## 4. Primary Sources

ให้ความสำคัญกับ Primary Source เมื่อสามารถตอบคำถามได้โดยตรง เช่น:

- เอกสารจากองค์กรเจ้าของข้อมูล
- เอกสารทางกฎหมายหรือมาตรฐานจากหน่วยงานที่เกี่ยวข้อง
- งานวิจัยต้นฉบับ
- รายงานผลโดยผู้เก็บข้อมูล
- Documentation จากผู้พัฒนา

---

## 5. Secondary Sources

Secondary Sources ใช้ได้ดีสำหรับ:

- บริบท
- การสรุป
- การเปรียบเทียบ
- การค้นหา Primary Source ต่อ

แต่ไม่ควรแทนที่ Primary Source เมื่อ Primary Source เข้าถึงได้และมีความสำคัญต่อ Claim

---

## 6. Search Results and Snippets

Search result snippets ใช้สำหรับค้นหาและค้นพบ Source ได้ แต่ไม่ควรถือเป็น Evidence หลักเมื่อสามารถเปิด Source ต้นทางได้

---

## 7. User-generated Sources

Community หรือ User-generated content มีคุณค่าเมื่อคำถามเกี่ยวกับ:

- ประสบการณ์จริง
- ปัญหาการใช้งาน
- ความเห็นของผู้ใช้
- สัญญาณหรือแนวโน้ม

แต่ต้องไม่ยกระดับประสบการณ์รายบุคคลเป็น Fact ทั่วไปโดยไม่มี Evidence เพิ่มเติม

---

## 8. Conflicts Between Sources

เมื่อ Source ขัดแย้งกัน:

1. ตรวจว่าอ้างถึงช่วงเวลาเดียวกันหรือไม่
2. ตรวจ Definition และ Methodology
3. ตรวจว่าเป็น Fact เดียวกันจริงหรือไม่
4. ตรวจคุณภาพและ Directness
5. พิจารณา Independence และ Bias
6. แสดงความขัดแย้งหากยังสรุปไม่ได้

---

## 9. Source Freshness

ข้อมูลที่เปลี่ยนแปลงเร็วต้องตรวจความสดใหม่ให้เหมาะกับคำถาม เช่น:

- ราคา
- นโยบาย
- Software
- กฎหมาย
- ข่าว
- สถิติที่มีการอัปเดต

ข้อมูลเชิงประวัติศาสตร์หรือหลักการที่คงที่อาจใช้ Source เก่าได้หากเหมาะสม

---

## 10. Source Record

เมื่อ Source มีความสำคัญ ควรบันทึก:

- Title
- Publisher / Author
- Publication Date
- URL / Identifier
- Access Date เมื่อเหมาะสม
- Source Type
- Relevant Claim
- Limitations

---

## 11. Prohibited Practices

ห้าม:

- สร้าง Source ปลอม
- อ้าง Source ที่ไม่ได้ตรวจสอบ
- อ้างจาก Snippet แทน Source โดยไม่มีเหตุผล
- ตัด Context เพื่อเปลี่ยนความหมาย
- ใช้ Source เดียวสนับสนุนข้อสรุปกว้างเกินกว่าที่ Source รองรับ
